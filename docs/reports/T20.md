## What changed
- `backend/app/routers/alerts.py`: Implemented scoped alerts API:
  - `GET /api/alerts`: Supports `unread_only`, `kind`, `limit`, `offset`, and returns `X-Total-Count` header. Role-based scoping: regional sees within region, bureau officer sees bureau alerts, management/admin see all.
  - `GET /api/alerts/unread-count`: Returns `{"count": <int>}` scoped to user role.
  - `POST /api/alerts/{alert_id}/read`: Scoped mark-as-read, returns 404 if out of user scope.
  - `POST /api/alerts/read-all`: Marks all user-scoped unread alerts as read.
- `backend/app/services/alerts.py`: Added deduplication support when `dedupe_key` is provided (suppresses identical kind, case_id, bureau_id on the same calendar day).
- `backend/tests/test_alerts.py`: Unit and integration tests covering role scoping, mark-read ownership, unread count, mark all read, and deduplication.
- `frontend/src/api/alerts.ts`: Typed API client for alerts endpoints.
- `frontend/src/pages/AlertsPage.tsx`: Enhanced Alerts UI with type filter dropdown, unread-only toggle, mark-all-read button, case reference links, and responsive badges.
- `frontend/src/components/Layout.tsx`: Bell notification icon with live unread count badge in header, polling at 15s interval.
